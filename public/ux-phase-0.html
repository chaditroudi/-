Governing rule. Complexity is never reduced by deleting features — it is reduced by moving it into routing, defaults, and progressive disclosure. Every finding below keeps the full MES brain on the server and gives the worker a thin, fast face.

D

Phased roadmap

Sequenced so the app stays usable throughout. Priority = UX impact × frequency × business importance × error reduction. High-frequency operator pain is fixed before low-frequency polish.

P0Phase 1–2

Design-system foundation + top operator workflow

Consolidate tokens (color, type, spacing, semantic status) and the shared table / form / drawer / command-menu primitives. Then rebuild the single most-used flow (QC decision or stock move) end-to-end as the reference pattern. Behavior preserved, verified against existing tests.

P1Phase 3–4

Navigation + data-dense experiences

Ship the grouped, role-aware IA on top of roleAccess. Unify the four stock tabs into one work-center. Bring saved views, multi-filter, bulk actions, and inline edit to the highest-volume tables (stock, requisitions, receptions).

P2Phase 5

Role home + exception-first dashboards

"À faire aujourd'hui" task queues per role; make normal operations quiet and exceptions loud — overdue work, deviations, approval backlog — each drilling to records and an action. Actionable notifications everywhere (approve/sign in place).

task homeexception cockpitaction notifications
P3Phase 6–7

Consistency, localization & validation

Apply the system to secondary modules; wire operator screens to useTranslation and close the Arabic gap on the daily-work path; extend offline beyond reception. Validate with real task-time and click measurements against this baseline.

✓

Regression gate on every change. Before shipping: "Can the user still do everything they could before?" Functionality, business rules, permissions, API contracts, validation, and workflows are preserved — the full test suite (currently 212/212) stays green.
